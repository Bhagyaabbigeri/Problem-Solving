Java Algorithms: Array Manipulation

Two Sum: The Classic Interview Problem

How do you find two numbers in an array that equal a specific target? We journey from the naive brute-force approach to the optimized Hash Map solution, analyzing time complexity every step of the way.

The Problem Solving Pipeline

"Given an array of integers, return indices of the two numbers such that they add up to a specific target."

1. Chat with the Strategist (The Prompt)

You: "I see the problem asks for indices, not the numbers themselves. Is that distinction important?"
Strategist: "Crucial. If the input is [2, 7, 11, 15] and target is 9, returning the values [2, 7] is wrong. You must return their positions, [0, 1]."
You: "Can I use the same element twice?"
Strategist: "No. The prompt explicitly states 'you may not use the same element twice'. This means if your target is 6 and you have a 3 at index 0, you cannot add index 0 to itself. You must find a different index holding another 3." 
// Method Signature
public int[] twoSum(int[] nums, int target) {
    // 1. Input: Array of integers
    // 2. Input: Target integer sum
    // 3. Output: Array containing two indices
    return new int[] {};
}
Edge Cases

Always verify constraints. The problem guarantees exactly one solution, so you don't need to handle "no solution" cases or empty return paths, which simplifies logic. However, always check if the array has negative numbers (it does here, via constraints), which affects sorting approaches.

2. Chat with the Brute Forcer (Naive)

You: "The simplest way is to just check every pair. I'll loop through the array, and for every number, loop through again to find a match."
Brute Forcer: "That is the definition of O(n²). If the array has 10,000 items, you perform roughly 100,000,000 operations. The grid shows every possible combination being checked." 
for (int i = 0; i < nums.length; i++) {
    for (int j = i + 1; j < nums.length; j++) {
        if (nums[i] + nums[j] == target) {
            return new int[] { i, j };
        }
    }
}
The Inner Loop Start

Notice the inner loop starts at j = i + 1. This optimization avoids two issues: checking the same element against itself (which is banned) and checking pairs twice (checking index 0 vs 1, then 1 vs 0). This cuts the work in half, but it remains O(n²).

You: "Is O(n²) really that bad for a LeetCode problem?"
Timekeeper: "LeetCode constraints often go up to 10⁴ or 10⁵. A modern computer can handle roughly 10⁸ operations per second. An O(n²) solution on 10⁴ elements is 10⁸ ops—barely acceptable. On 10⁵ elements? 10¹⁰ ops. Time Limit Exceeded."

Big-O Notation

Big-O describes the worst-case growth rate. In interviews, if you write a solution that works but grows exponentially with input size, you will likely fail the efficiency portion of the assessment. We need Linear Time O(n) or Logarithmic Time O(log n).

4. Chat with the Architect (HashMap)

You: "How can we solve this without two loops?"
Architect: "We trade Space for Time. By using a HashMap, we can store numbers we have seen and their indices. A HashMap allows us to check if a number exists in O(1) time, instantly removing the need for the second loop." 
// Import the HashMap class
import java.util.HashMap;
import java.util.Map;

// Initialize the data structure
Map map = new HashMap<>();

// map.put(Key, Value) -> Stores the number and its index
map.put(2, 0);
map.put(7, 1);
Key vs Value

For this problem, the Key must be the Number from the array (because we need to search for the number). The Value must be the Index (because that is what we need to return). If you swap them, you lose the ability to look up the number efficiently.

5. Chat with the Logician (The Complement)

You: "Okay, I have a HashMap. But how does it help me find the pair? Do I still loop?"
Logician: "You iterate through the array once. For every number you encounter, calculate the Complement. The complement is simply Target - Current Number. If Target is 9 and Current is 2, the Complement is 7."
You: "And then I check if that complement exists in the map?"
Logician: "Precisely. You don't search the array for the 7. You ask the HashMap, 'Do you have a key for 7?' If yes, you have found your match." 
int current = nums[i]; // e.g., 2
int complement = target - current; // 9 - 2 = 7

// Logic:
// "If I have a 2, I need a 7 to complete the pair."
Mathematical Logic

This logic works because addition is commutative (A + B = B + A). If we are at index 0 (value 2), we ask "Is there a 7?". If the map doesn't have 7 yet (because we haven't reached index 1), we store 2. When we eventually reach index 1 (value 7), we ask "Is there a 2?". The map will say YES, because we stored it earlier.

6. Chat with the Validator (Lookup)

You: "So the `containsKey` method is the secret weapon?"
Validator: "Yes. Unlike an array where you must scan every element to check existence, a HashMap uses hashing algorithms to jump directly to the bucket where the item should be. This is O(1) access time."
You: "What happens if it's not in the map?"
Validator: "It returns false instantly. No loops, no waiting. We then add the current number to the map and move to the next index." 
if (map.containsKey(complement)) {
    // Found it! Return the index of the complement,
    // and the current index 'i'.
    return new int[] { map.get(complement), i };
}

// Not found? Store current number for future checks.
map.put(nums[i], i);
Hash Collision

Technically, HashMaps are O(1) on average, but can degrade to O(n) in the worst case due to hash collisions (many keys landing in the same bucket). However, Java's implementation is highly optimized, and for interview purposes, we treat HashMap lookups as constant time O(1).

7. Chat with the Optimizer (One Pass)

You: "Do I need to populate the map first, and then loop again to check?"
Optimizer: "No! That would be 'Two Pass'. We can do it in One Pass. We check the map *before* inserting the current number. Since the problem guarantees a solution, eventually we will find a complement that was inserted in a previous iteration." 
for (int i = 0; i < nums.length; i++) {
    int complement = target - nums[i];
    
    if (map.containsKey(complement)) {
        return new int[] { map.get(complement), i };
    }
    
    // Store AFTER checking to avoid using same element twice
    map.put(nums[i], i);
}
Order of Operations

The order is critical. We Check First, Insert Later. If we inserted the current number into the map before checking, and the complement happened to be the current number itself (e.g., target 6, current 3), we might accidentally match the number with itself, violating the "same element twice" rule.

↓ Final Solution

8. Chat with the Reviewer (Solution)

You: "We did it. O(n) time complexity, O(n) space complexity."
Reviewer: "Correct. We iterated through the list once, performing O(1) operations each time. The space is O(n) because, in the worst case, we store almost all elements in the map before finding the pair. This is the optimal solution for unsorted arrays." 
class Solution {
    public int[] twoSum(int[] nums, int target) {
        Map map = new HashMap<>();
        
        for (int i = 0; i < nums.length; i++) {
            int complement = target - nums[i];
            
            if (map.containsKey(complement)) {
                return new int[] { map.get(complement), i };
            }
            map.put(nums[i], i);
        }
        throw new IllegalArgumentException("No solution");
    }
}
Follow-up Answer

The prompt asked if we can do better than O(n²). Yes. We achieved O(n). If the input array was already sorted, we could use the Two Pointer technique to achieve O(n) time with O(1) space, but since the input is unsorted and we need indices, the HashMap approach is the standard optimal solution.

Algorithm mastery comes from understanding the trade-offs between Time and Space. The HashMap reduces Time complexity by sacrificing Space.
